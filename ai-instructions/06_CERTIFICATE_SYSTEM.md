# SriDwar — Certificate & PDF System

## Three Separate Documents

### 1. Acknowledgement Certificate
Immediate acknowledgement after an applicable booking/submission/selection.
- JPG/PNG image
- available immediately when workflow permits
- service-specific design
- dynamically populated
- downloadable/savable/shareable
- available again from Profile where applicable

It does NOT mean the service/Puja has already been completed.

### 2. Confirmation / Information PDF
Separate document containing transaction/service/confirmation information.
- Do not embed the acknowledgement certificate image inside it.
- Preserve existing PDF architecture where working.
- Keep customer data dynamic.

### 3. Final Personalized Completion Certificate
Prepared separately by SriDwar after actual service completion and sent later by the SriDwar team.

## Dynamic Fields
Where applicable, populate:
- actual user name
- Reference ID
- date
- invoice/payment details
- service/Puja/Seva
- submitted-as information
- temple name
- transaction details

Never use stale or generic “Devotee” data when actual user information exists.

## Design
Use the latest approved service-specific palm-leaf assets as source of truth. Do not revive deleted/obsolete assets.

## Alignment
Dynamic text must be centered and positioned consistently relative to labels and design elements.
